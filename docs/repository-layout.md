# Reproduction entry points and retained evidence

Use [artifact/run.sh](../artifact/run.sh) for all maintained benchmark modes:
`smoke`, `paper22`, `interleaved28`, `codeswitch28`, and `full28`.
The [guide](../artifact/README.md) describes builds, resources and output.
New runs default to one warmup and one sample; full-size runs use 16 workers
and only 2^28. Parameter search and distance-check tools remain in `scripts/`.

## Evidence kept in the active tree

| Directory under `artifact_results/` | Why it is retained |
| --- | --- |
| `2026-10-14-prime-four` | Original paper-sized four-code samples, proofs, source and hashes. |
| `2026-10-15-aws-r7a4x-n28` | Original common-interleaved AWS measurements and provenance. Older complete-IOPP rows are labeled historical. |

| `2026-10-15-era-joint-params` | Final parameter-selection rationale and search evidence. |
| `2026-10-15-era-joint-profile` | Before-optimization profile supporting the final speedup comparison. |
| `2026-10-15-proof-size-audit` | Paper-versus-wire accounting and self-contained reproduction input. |
| `2026-10-16-era-compact` | Final optimized measurements, profiles and proof-identity evidence. |
| `2026-10-16-submission-validation` | Docker validation, tests, reference hashes and additional full-size run. |

Old tables, Bolt experiments, Spot continuation attempts, checkpoint trials,
C++ shuffle microbenchmarks and their launch scripts are no longer active
entry points. Before removal they were archived, with original paths and
verified hashes, in ignored
`results/cleanup-20261016/superseded-experiments.tar.gz`.
`history-manifest.json` indexes that archive; `removed.json` records deletions.
Compact diagnostics from discarded development runs and the small before/after
optimization proofs are retained there too. These historical records are not
inputs to the final reproduction workflow.

## Large payloads and releases

Current and historical release files and their checksums are under
`results/submission-20261016/`. The main prepared submission is
`era-codes-artifact-20261016-submission-llncs.tar.gz`; see
[the submission record](artifact-submission.md) for its exact hash and version.
The following supporting and historical archives are also retained:

- `era-codes-artifact-20261016-original.tar.gz`: the original tested submission source.
- `era-codes-evidence-20261016.tar.gz`: ten reference proofs, original source
  snapshots and measured binaries, under `reference-payloads/`.
- `era-codes-dependencies-20261016.tar.gz`: pinned Cargo sources, Linux wheels
  and dependency notices.
- `aws-backup.tar.gz`: complete private backup of the four completed campaigns,
  under their original campaign directory names.
- `container-validation.tar.gz`: the final container validation including proofs.

Expanded dependency/proof/campaign duplicates and temporary build directories
have been removed; expanded source releases are retained for inspection.
Extract an archive into a fresh temporary directory when a full
proof or historical source snapshot is needed; no AWS access is required.
The release archives remain unchanged by repository cleanup.
The refreshed source package is recorded in [the submission record](artifact-submission.md).

`target/release/` is retained and ignored by Git. Development build caches may
be regenerated by Cargo. All scientific Rust code and final benchmark parameters
remain unchanged by this cleanup.

## Packaging

The paper PDF is retained as `artifact/paper.pdf`; packaging no longer requires
a sibling paper checkout. From this repository, create a fresh package directory:

```sh
python3 -B artifact/package.py results/new-artifact-package
python3 -B artifact/validate.py evidence results/new-artifact-package
```

The package excludes historical runs and local build output. It carries the
exact Rust sources, selected raw evidence, dependency notices, paper PDF and
reviewer commands. An optional development-only cleanup history archive is not
required to build or regenerate either final experiment.

The current project name in documentation is ERA codes, and the Cargo package
is `era-codes`. Historical source snapshots and wire-domain identifiers retain
their original values for provenance and proof compatibility. Local filenames
for historical release archives were renamed without changing their bytes.
